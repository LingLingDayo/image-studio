# 优化评估

[返回 README](../README.md)

## 判断标准

目标是“简约、易用的生图工作台”，不是复杂的模型管理后台。主路径应保持：**连接服务 → 描述画面／添加参考图 → 生成 → 查看与下载**。

现有 Vue + Pinia、provider、任务调度与本地存储的分层总体合理。本轮保留有效边界，围绕明确的体验与逻辑问题重构，没有增加新框架、依赖或云端能力。

## 后续实测与模型控件简化（2026-11-06）

用户配置服务后，使用单张、低质量、请求尺寸 1024×1024 的最小生图参数进行真实验证。没有将服务地址、API Key 或生成图片写入仓库。

| 实测项 | 结果 |
| :--- | :--- |
| 提示词优化 | HTTP 200，约 3.5 秒；撤销、重做通过 |
| 文生图 | HTTP 200，约 34.5 秒；图像成功保存与显示 |
| 参考图编辑 | HTTP 200，约 29.1 秒；蓝色圆形成功改为橙色 |
| 保存与复用 | 两张作品刷新后保留；收藏与筛选、原始设定复用、参考图恢复通过 |
| 下载与转换 | 原图像素保持不变；显式 JPEG 导出确实转换为 JPEG，而不是只改扩展名 |
| 优化模型控件 | 单个可自定义输入的下拉框；刷新位于箭头左侧，实际获取 7 个模型且不覆盖手动值；不再显示独立按钮与绿色成功条 |
| 响应式与键盘 | 320 / 390 / 1280 像素布局、下拉裁剪边界及 Escape 操作通过 |

实测服务虽然接受了 JPEG 与 1024×1024 请求，但返回 PNG、1254×1254。工作台不应把请求设定冒充实际结果：现按 PNG / JPEG / WebP 字节签名识别 MIME 与下载格式，并用 `targetFormat` 单独保留请求格式，兼容以前的记录，复用时仍恢复原始设定。

此次共完成两次真实生图请求和一次真实优化请求。补充回归后，全量 37 个测试文件、372 个测试及类型检查通过；单元测试与本地真实接口配置已隔离。未新增依赖、未运行 build，测试截图和图片仅存于忽略目录。

## 后续优先级执行状态

### 1. 工具链一致性：核心问题已解决

已升级现有 Vue 插件到 6.0.10，与 Vite 8.2.2 匹配；标准 `npm ci` 已验证，无需忽略 peer 校验。新增独立 `npm run typecheck` 与 Windows / Node.js 22 的 GitHub Actions 质量检查。流水线配置已加入仓库，远端运行仍需推送后验证。

lint 尚未接入：已申请 `eslint`、`@eslint/js`、`eslint-plugin-vue`、`typescript-eslint` 四个开发依赖，未获批准前不安装、不宣称 lint 通过，也不做全库格式化。

### 2. 接口协议能力：已实现明确适配

Chat Completions、Responses、Messages 使用各自请求体、认证头和文本解析；Responses 使用原生 `input` 与 `output`，不再只是换路径。Chat 保留现有兼容请求字段；Messages 沿用既有版本头。模型列表按所选协议认证，端点变化清理旧列表并忽略过期响应。

未知端点明确拒绝；服务实际模型权限与数据留存政策仍由所接服务决定。协议实现和官方资料见 [配置指南](configuration.md#提示词优化可选)。本轮协议使用合同测试与 mock 验证，没有新增付费请求。

### 3. 数据与任务生命周期：已落地最小完整功能

在设置 → 通用设置新增折叠的“作品备份”：导出本地 JSON、选择并校验文件、内联预览、确认合并。只包含当前作品字段、图片、参考图与生成参数，不含密钥和偏好。合并跳过重复，不按备份 ID 覆盖本站 ID；事务失败不留下半批作品。存储增删改及导入均在事务完成后报告成功，失败时不提前释放显示 URL。

合法旧 Blob / 本地 Data URL 可以内存兼容，未知记录不强行转换、远程地址不自动访问；无法识别的记录会阻止不完整导出。备份不是未知历史字段的原始数据库镜像，无法恢复此前已删除的数据。

当前限制为 128 MiB JSON、1000 张作品、单图 32 MiB、图片与参考图累计 80 MiB。更大作品库需后续单独设计分片或流式备份，不能静默截断。

任务历史仅保留最近 30 个成功/取消任务；活跃、排队、失败待复用任务受到保护。显式移除失败任务释放其历史引用，迟到的成功清理不移除已重试任务，不撤销输入区拥有的 URL。

### 4. 独立职责拆分：已完成

`ReferencePreviewModal` 独占参考图预览、原生/页面内全屏、导航、焦点与滚动恢复；`App.vue` 只负责应用协调。`usePromptOptimizer` 管理优化请求、撤销/重做、取消与请求版本，输入/配置变更或卸载后旧响应不能覆盖新内容；`PromptBar` 负责展示与输入事件。

未引入新的状态机或通用工作流引擎，没有为了行数缩短而机械拆分。
