# 配置与部署

[返回 README](../README.md)

## 先选择配置方式

| 场景 | 推荐方式 |
| :--- | :--- |
| 个人本地使用 | 在设置中填写生图接口地址和 API Key；提示词优化按需配置 |
| 部署固定接口的工作台 | 用环境变量固定接口地址，使用者在浏览器填写自己的 API Key |
| 调整默认模型或提示词优化模板 | 使用下方的构建时环境变量 |

工作台是纯前端应用，Nginx 仅提供静态文件，不代理 API、不保存作品，也不会隐藏浏览器发出的请求。生图服务与提示词优化服务相互独立，不会自动共用凭据。

## 环境文件与生效时机

本地开发需要预设配置时，在 PowerShell 中执行：

```powershell
Copy-Item .env.example .env.development.local
```

编辑所需变量后运行 `npm run dev`。改变环境文件后需重启开发服务。未填写的变量使用源码默认值，接口地址和 Key 可以在界面设置。

`VITE_*` 在开发服务启动或生产构建时注入，**不是容器运行时配置**。生产资源构建完成后，仅修改 `.env` 或重启 Nginx 不会改变这些值，必须重新构建资源与镜像。

非空的生图/优化接口地址与 API Key 环境变量优先于浏览器保存的值，对应设置输入框被隐藏；模型与调用端点环境变量只提供默认值，浏览器已有选择优先，并可在界面修改。

> `VITE_*` 会进入前端资源，浏览器用户能够读取。公开部署应留空 API Key 变量，使用受限、可撤销的个人令牌，不要把服务器密钥打进前端包。`.env` 和本地环境文件已被 Git 忽略，但仍应妥善保管。

## 构建时变量

### 生图服务

| 变量 | 用途 | 未填写时 |
| :--- | :--- | :--- |
| `VITE_IMAGE_API_BASE_URL` | OpenAI Images 兼容服务的 Base URL，可带或不带 `/v1` | 在界面填写 |
| `VITE_IMAGE_API_KEY` | 固定生图 API Key，非空时锁定界面凭据 | 在界面填写 |
| `VITE_IMAGE_API_KEY_HINT` | API Key 输入框的引导文案 | `令牌只保存在本机浏览器，不会上传到工作台服务器` |

生图模型在底部参数栏选择，候选列表来自配置服务的 `/v1/models`；实际支持哪些模型和参数由服务决定。

### 提示词优化（可选）

| 变量 | 用途 | 未填写时 |
| :--- | :--- | :--- |
| `VITE_OPTIMIZER_API_BASE_URL` | 优化服务的 Base URL | 在界面填写 |
| `VITE_OPTIMIZER_API_KEY` | 固定优化 API Key，非空时锁定界面凭据 | 在界面填写 |
| `VITE_OPTIMIZER_API_KEY_HINT` | 优化 API Key 输入框的引导文案 | 与生图 Key 的默认提示相同 |
| `VITE_OPTIMIZER_MODEL` | 优化模型的初始名称 | 空，需选择或填写模型 |
| `VITE_OPTIMIZER_ENDPOINT` | 优化请求路径 | `/v1/chat/completions` |
| `VITE_OPTIMIZER_PROMPT_TEMPLATE` | 自定义优化指令，使用 `{prompt}` 插入用户提示词 | 内置优化模板 |

环境示例不绑定特定模型，优化模板留空时使用内置默认值。模型名称请填写接入服务实际支持的名称，或在设置中主动获取模型列表。

优先使用 `/v1/chat/completions` 兼容接口。界面也提供 `/v1/messages`、`/v1/responses` 路径，具体是否兼容取决于服务的请求与响应格式，不保证仅切换路径就能适配所有厂商原生 API。

模板包含 `{prompt}` 时会替换所有该占位符；没有占位符时，会把用户提示词附加在模板后。建议保留占位符，使指令结构清晰。

## Docker 部署

### 前提

需要本地 Node.js/npm 与 Docker Compose。镜像只包含 Nginx，Dockerfile 从本地 `dist/` 复制资源，**不会在镜像内安装依赖或构建前端**。

首次部署在 PowerShell 中执行（已有 `.env` 时不要覆盖）：

```powershell
Copy-Item .env.example .env
# 编辑 .env；公开部署请留空两个 VITE_*_API_KEY
npm ci --legacy-peer-deps
npm run build
docker compose up -d --build
```

当前安装命令的临时兼容参数见 [开发指南](development.md#当前依赖兼容问题)。这里的 build 用于生成部署产物，不用于日常修改验证。

默认访问 [http://127.0.0.1:3000](http://127.0.0.1:3000)。部署前端配置变更时，重新执行资源构建与 Compose 启动命令。停止本项目容器：

```powershell
docker compose down
```

### 容器运行时变量

以下值由 Docker Compose 读取，不进入前端资源：

| 变量 | 用途 | 默认 |
| :--- | :--- | :--- |
| `BIND_HOST` | 宿主机监听地址 | `127.0.0.1`，仅本机访问 |
| `HOST_PORT` | 宿主机 HTTP 端口 | `3000` |
| `NGINX_FRAME_ANCESTORS` | CSP 中允许嵌入工作台的 iframe 父来源 | `*`，允许任意站点 |

- 通过本机 Tunnel 或反向代理接入时，保持 `BIND_HOST=127.0.0.1`。
- 需要其他设备直接访问时，可设为 `0.0.0.0`，并自行配置防火墙、HTTPS 与访问控制。
- 嵌入其他后台时，将 `NGINX_FRAME_ANCESTORS` 设为该后台的 origin，例如 `https://gateway.example.com`；多个来源用空格分隔。不需要嵌入时可设为 `'none'`。
- Compose 内部固定 `NGINX_ENVSUBST_FILTER`，只替换 iframe 来源配置，避免破坏 Nginx 自身的变量；一般无需修改。

## 连接与数据常见问题

**填写 Key 后仍然失败**

确认 Base URL 指向接口服务，不是登录页；确认 Key 有对应模型权限及额度。工作台直接跨域调用接口，服务必须允许当前工作台来源的 CORS 请求、相关请求方法和认证头。HTTPS 页面调用 HTTP API 可能被浏览器混合内容策略阻止。查看页面错误信息与浏览器网络面板，不要把完整 Key 发给他人排查。

**模型列表获取失败**

部分服务没有兼容的 `/v1/models`。检查接口权限和 CORS；优化模型可手动填写。列表返回成功也不等于模型一定支持所选生图参数。

**换域名、浏览器后找不到作品**

作品按浏览器及站点 origin 隔离，协议、域名或端口改变都会成为不同站点。当前没有云同步或完整作品库导入导出，迁移前请下载重要图片。

**刷新页面后任务消失**

任务状态在内存中，不会在刷新后恢复；已成功保存的作品仍在 IndexedDB 中。生成过程中请保持页面打开。取消浏览器请求不保证服务端停止执行或免除计费，需以接口服务规则为准。

**升级早期版本前需要注意什么**

当前本地数据库版本为 4。升级时保留既有作品存储与原始记录，只补齐缺失索引，不再主动清空旧作品。未知历史记录格式不保证可展示，也无法恢复以前版本已删除的数据；升级前仍应备份重要图片。
